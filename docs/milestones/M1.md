## 2. What M1 does *not* need

The M1 hand-proof (M0 §4a) drove the whole path through commands and verified it:

```text
artboard.new -> file.place -> object.cropImage -> object.maskImage -> text.create
  -> document.serialize -> document.export (PNG) -> document.exportPdf
```

with the PDF's trim box equal to the artboard, its bleed box grown by the bleed, its media box
carrying the marks, one page per artboard, a Type0 embedded subset font, the cropped image 32×32
in the PDF, and a byte-identical save/reopen round trip with every id preserved.

**So M1 adds no engine capability.** What it adds is the comic model that records *which panel a
frame belongs to*, and the commands that create and edit that model. Everything visual — panels,
clips, balloons, lettering — is an existing document object the comic layer refers to by id.

#### 5.4a The retracted assertion, and a test of the reviewer's own that I changed

W2's round 2 raised a finding that **retracted a guarantee I had asserted**. I told the implementer
that a page's last panel would land exactly on the content box wherever the page sat; that is the f64
identity `a + (b - a) == b`, and it is simply false — a `PanelRect` is a position *and* a size, so no
rearrangement of the arithmetic avoids the rounding. The reviewer found it away from the origin; the
implementer reproduced it (47 922 pages, worst error 0.256 ULP) and restated the guarantee at the
strength f64 actually delivers: **≤ 1 ULP of the page's coordinate magnitude, and exact when the page
starts at the document origin**. The doc was corrected to match. The same round also replaced the
absolute geometry tolerance with a relative one, `tolerance_at(scale) = max(1e-9, 8·|scale|·EPSILON)`,
because an absolute epsilon cannot be right for both a 1e3pt and a 1e10pt page.

The assertion that had to change lived in **the reviewer's own test file**,
`crates/comic-layout/tests/round2_reviewer.rs`. I made that change myself rather than hand the
implementer another agent's test to edit — the rule that an implementer does not touch the reviewer's
tests is worth more than the convenience. The exact `assert_eq!` is **kept for origin-anchored pages**,
where it is true and load-bearing, with the ULP bound applied only elsewhere.

The first attempt landed on the **wrong occurrence** of a repeated block: the file holds two similar
sweeps, and the one I hit has no `origin` in scope, so the edit did not compile (`E0425`). That
compile error is the only reason it was caught; a two-line change in a 400-line file is exactly the
kind that would otherwise have silently moved an assertion to the wrong test. Reverted and applied to
the intended test, which the round-3 reviewer is asked to judge as a reviewer rather than accept.

Crate state after the change: **263 green** (172 lib + 8 layer rules + 27 `PanelRect` + 27 round-1
reviewer + 17 lettering round-1 reviewer + 12 round-2 reviewer).

##### M1-F2 — the tolerance overflowed at a *finite* scale, and the reorder fixes it

The confirmation raised two more preferences, and the first one I **took further than a comment**. The
implementer had left the finite ceiling alone in round 4 reasoning that *"one ULP is ~`2e292`pt and the
defect isn't representable"*. **That is false**, and the reviewer showed it: on a `2.25e307`pt page a
`5e299`pt overlap is perfectly representable and is **silently unreported**.

The cause is **evaluation order**, not magnitude:

```text
8.0 * scale.abs() * f64::EPSILON     // parses as (8.0 * scale) * EPSILON
```

`8.0 * 2.25e307` = `1.8e308` exceeds `f64::MAX` and overflows to `+inf` **before** the multiply by
epsilon, so the tolerance is `inf`, `GEOMETRY_TOLERANCE.max(inf)` is `inf`, every threshold holds, and
the geometry check is **switched off by a finite input** — the exact failure mode round 4 closed for
non-finite input, reached a different way. Reordering to `TOLERANCE_ULPS * f64::EPSILON * scale.abs()`
computes `1.776e-15` first, and times even `f64::MAX` gives `3.19e293`: **finite everywhere**.

**I verified the reorder is behaviour-preserving before dispatching it**: at `1e3, 1e5, 1e6, 1e7, 1e8`
and `1e12` the two orders are **bit-identical**, and at `1e12` both give exactly
`0.0017763568394002505` — the value the masking test pins. So the fix costs nothing at any reachable
scale and closes a silent hole, which is why it was worth a fifth pass rather than a comment edit.

The second preference was comment-only and is the milestone's signature failure again: `page`'s guard
justified its skip with *"`faults` cannot size a tolerance from an infinite magnitude … the geometry
check would be silently off"* — a sentence the **same round-4 commit made false**. And the "`5.6e12`pt
is wider than the solar system" claim is `1.98e9` m ≈ **1.4 Sun diameters**, overstated ~4500× (the
reviewer's own miss, which it flagged against itself).

##### A bug in my own verification tool, found because it cried wolf

`check-reviews.sh "" M1` began reporting **`GAP docs/reviews/M1-acceptance.md`** — *"no 'Reviewer:'
line, missing Round 1 section, Round 2 has no verdict"* — and exiting **1**. The file is an
**implementer report**, not a review record; W5's review legitimately lives in a sibling
`M1-acceptance-review.md`, which **my own brief told it to use**. So my checker was penalising a
correctly-recorded implementation, and the failure mode of that is worse than a missed gap: **a
verifier that cries wolf gets ignored.**

My first fix was wrong and I caught it by testing rather than assuming: I guarded on *"no `Round`
heading"*, but the implementer's report contains **`### Round 2 — the gate, green on all seven steps`**
as prose, so the guard never fired. The right discriminator is that a review record has a `Reviewer:`
or `Verdict:` line and an implementer report has **neither**. Verified **both** ways, not just the
happy path:

| case | expected | got |
|---|---|---|
| pairing present | OK, exit 0 | OK, exit 0 ✔ |
| sibling hidden | GAP, exit 1 | GAP, exit 1 ✔ |
| a review record with a `Reviewer:` line but no rounds | GAP | GAP ✔ — **so the change does not mask real gaps** |

That third row is the one that matters: a fix that made the checker pass by making it weaker would be
the worst possible outcome, so I tested that it still fails on a genuinely incomplete record.
